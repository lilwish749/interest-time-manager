# 执行卡标注规范

> **执行卡写得含糊，整个计划就退化成待办清单。**
>
> 周计划的价值不在「几点做什么」，而在「这一小时具体做完什么」。`scheduler.js` 只负责算时间、顺序、间隔和容量；**做什么、交付什么、注意什么**全靠执行卡。一条含糊的执行卡，会把排好的时间表变回「学 Python 1 小时」这种没有信息量的待办。

## 1. 执行卡是什么

每个活动在 `data/activities.js` 里带一个 `cards` 数组，2–4 张，按「第一次接触 → 能独立完成」递进：

```js
{
  id: "python-data-video",
  // ...活动的 8 轴字段（D1/D2/focusNeedMin/D4/D5/D6/D7/channel/bestTime）不动...
  cards: [
    { step: 1, action: "…", deliverable: "…", tip: "…" },
    { step: 2, action: "…", deliverable: "…", tip: "…" },
    { step: 3, action: "…", deliverable: "…", tip: "…" }
  ]
}
```

排程时按 `lms.done.v1` 里该活动**已完成的步数**决定这次用第几张卡；全部做完就回到第 1 张并标注「复习」。

## 2. 四条硬性质量要求

| # | 要求 | 判断标准 |
|---|---|---|
| 1 | `action` 必须是「动词 + 具体对象 + 数量或范围」 | 第三方能判断做没做完（有数量、有范围、有终点） |
| 2 | **禁止**出现「了解」「熟悉」「培养」「学习一下」「接触」这类词 | 测试用正则 `/了解\|熟悉\|培养\|学习一下\|接触/` 直接拦 |
| 3 | `deliverable` 必须是一个**能看见的东西** | 文件 / 录音 / 照片 / 截图 / 笔记条数，不能是「理解了」 |
| 4 | `tip` 写一句真实的坑，≤ 30 字 | 一句话说清「容易卡在哪、卡住了怎么办」 |

同一活动的 2–4 张卡要能看出**难度在涨**。

## 3. 三档行为锚点（产出压力 D5）

`D5`（产出压力）的数值锚点来自 [ANNOTATION.md](ANNOTATION.md)。执行卡里的 `deliverable` 强度必须与 `D5` 对得上，否则用户会拿到一份和评分不符的安排：

| D5 | 0.2（做完就算） | 0.5（有可见产物） | 0.8（要对得起观众） |
|---|---|---|---|
| 交付物强度 | 随手记、勾掉即可 | 一个文件 / 一条录音 / 一张图 | 能拿给别人看、经得起挑刺 |
| 典型 `deliverable` | 「3 条提问记录」 | 「一张 5 阶灰度稿」 | 「一份可分享的临摹对比图」 |
| 收尾动作 | 记一笔就停 | 导出 / 保存 / 命名 | 自检一遍再交出去 |
| 对应 `tip` | 别纠结格式 | 先把主线跑通 | 先看整体再看细节 |

同理，其余字段与执行卡的呼应关系：

| 字段 | 高值 → 执行卡应该怎么写 |
|---|---|
| `D1` 认知强度 | 高：卡里要出现「先跑通一个小小的例子」，别一上来就啃全量 |
| `D2` 知识门槛 | 高：第一张卡要写明用哪个入门材料；低：可以直接上手做真实数据 |
| `focusNeedMin` 专注时长 | 高：一张卡的动作要能撑满一整段，别写成 5 分钟能做完的 |
| `D7` 反馈即时性 | 低：`deliverable` 要自带检查方式（跑一下、听一遍、对照原图） |
| `channel` 通道分布 | `hands` 高 → 动作以「动手做/改」为主；`read` 高 → 以「读+摘录」为主 |
| `bestTime` 最适时段 | 需要脑子最清楚的卡（如新概念第一次接触）放第 1 张，复习类放后面 |

## 4. 反例 → 正例

| 反例（含糊，退化成待办） | 正例（可验收） |
|---|---|
| 「了解一下 pandas」 | 「跟完教程第 1 节，用 pandas 把示例 CSV 读进来并打印前 5 行」 |
| 「熟悉一下音阶」 | 「单手把 4 小节慢速弹顺，节拍器 60，录一段 30 秒」 |
| 「培养设计感」 | 「选一张想临摹的图，用 30 秒画出 3 个缩略构图方案（火柴人级）」 |
| 「学习一下剪辑」 | 「导入 5 段素材，各裁到 3 秒，按时间顺序拼成一条 15 秒短片」 |
| 「接触一下 Arduino」 | 「把 LED 接到 13 号脚，写 5 行闪灯代码，烧录后录 10 秒视频」 |

## 5. 自查清单

新增或修改执行卡后，逐条打勾：

- [ ] 12 个活动都有 `cards`，每个 2–4 张
- [ ] 每张卡的 `action` 里有动词、有对象、有数量或范围
- [ ] 全库搜不到「了解 / 熟悉 / 培养 / 学习一下 / 接触」
- [ ] 每张卡都有 `deliverable`，且是能看见的东西
- [ ] 每张卡的 `tip` ≤ 30 字，说了真实的坑
- [ ] 同一活动的卡难度递增，能看出「第一次接触 → 能独立完成」
- [ ] 跑 `node tests/run.js`，「排程 · 执行卡完整性」两项全绿
